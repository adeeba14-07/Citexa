# Citexa — local setup and recovery

## Important security action
Do not share screenshots of `.env` files or commit `.env`. If a credential is visible in a screenshot, revoke and rotate it before continuing. Keep active credentials only in a local ignored `.env`; the project bundle should contain `.env.example` only.

## Run locally on Windows
1. Install Node.js LTS and pnpm (`npm install -g pnpm`).
2. Extract this folder and open the `Citexa-fixed` repository root in VS Code.
3. Copy `.env.example` to `.env`; add a reachable PostgreSQL URL with pgvector, a Groq API key, and matching Clerk publishable/secret keys if using real sign-in.
4. In Clerk, create a development application and set the allowed local domain to `localhost:5173`. Use the publishable and secret keys from that same application.
5. Run `pnpm install`.
6. Run `pnpm run setup` if this repository's setup script asks to install workspace/system prerequisites.
7. From the repository root run `pnpm run dev` (not only the frontend Vite command). This starts the API on `localhost:3001` and the web app on `localhost:5173`.

## Vite proxy `ECONNREFUSED`
This means Vite is running but its `/api` proxy cannot connect to the API at `http://localhost:3001`. Run `pnpm run dev` from the repository root so both processes start, then inspect the `[api]` lines in that same terminal. Confirm `.env` has a valid `DATABASE_URL`, restart after editing `.env`, and check that another program is not already using `API_PORT` (default `3001`). If you started Vite alone, stop it and use the root launcher. Persistent refusal means the API exited or could not connect to its database.

## Do not enable demo login
Set `DEMO_MODE=false` (or leave it unset once both Clerk keys are present). `dev.mjs` automatically chooses real Clerk authentication when both Clerk keys are configured. Do not set `VITE_DEMO_MODE=true`.

## Upload failures
The UI's “HTTP 500 Internal Server Error: Failed to generate upload URL” is generated by `POST /api/storage/uploads/request-url`. Check the API terminal immediately after reproducing it; the server logs the underlying exception. Confirm that the API process is running, that you restarted `pnpm dev` after editing `.env`, and that the request is authenticated by Clerk. The response intentionally does not expose internal error details to the browser.

## New chat
The tutor's “New chat” creates a conversation record in PostgreSQL. It requires a valid signed-in Clerk session, an existing course owned by that user, and the database schema to be applied. If it appears inert, inspect the browser DevTools Network tab for the POST to `/api/courses/:courseId/conversations`; a 401 means auth/session configuration, a 404 means course ownership/ID, and a 5xx means inspect the API terminal.
